MVP-006 Slice Draft

Drafted MVP-006 - Real Model Tools And Character State Patch as the next proposed active slice after MVP-005 landed on main. The previous MVP-005 active spec was archived under docs/plan/completed/mvp-005-structured-role-model-user-turn-foundation.html.

The slice was shaped from the user review discussion: before adding retrieval, scheduler, external productivity tools, Live2D, or incidents, the rebuilt runtime needs one real provider pressure test, a built-in model tool registry, and a Character State tool that lets the model request state patches without mutating durable state directly.

  • CT-01 owns the built-in model tool registry and tool-call decision contract.
  • CT-02 owns the env-gated NVIDIA provider adapter, with fake-client tests and no committed secrets.
  • CT-03 owns Character State types, default state, state brief creation, patch validation, and storage.
  • CT-04 owns validation-before-mutation runtime commit integration for visible replies plus optional state patches.
  • CT-05 owns CLI, inspect, docs, live-smoke instructions, and final integration review.

The draft keeps the local deterministic adapter as the default path, treats provider calls as explicit opt-in behavior, and records that any pasted provider token should be considered exposed and handled only through environment variables after rotation.

Follow-up review tightened the draft before implementation: provider selection is both CLI and environment based with CLI precedence, valid no-op character_state.patch calls are accepted with explicit no-op evidence, CT-02 no longer owns final chat CLI flag parsing, and "atomic" commit wording was narrowed to validation-before-mutation without a broad cross-file transaction framework.

MVP-006 Implementation

Implemented the MVP-006 slice on feature/mvp-006-provider-tools-state. The role model contract now uses mvp-006.tool_calls.v1 with ordered toolCalls, while the parser still accepts the MVP-005 action.visible_reply shape for migration compatibility.

  • Added built-in model tools for visible_reply and optional character_state.patch.
  • Added an env-gated NVIDIA-compatible chat-completions adapter with fake-client tests, redacted provider metadata, missing-key errors, and non-streaming request rendering.
  • Added Character State defaults, living-state brief creation, patch validation, no-op evidence, immutable before/after snapshots, and file-backed per-session state storage.
  • Integrated validation-before-mutation runtime handling for visible replies plus accepted changing or no-op state patches, with invalid patches rejecting the whole turn before visible messages are committed.
  • Updated chat CLI provider selection, trace-safe behavior, inspect output, storage codecs, and compatibility tests.

Parallel CT review was folded back into the coordinator branch before PR: provider diagnostics redact echoed API keys, raw-event brief text is checked against canonical state text, durable public reads reject state-file drift from accepted patch evidence, state writes no longer occur before visible conversation logging succeeds, and trace JSONL now summarizes provider, tool-call, and state-patch status.

Checks run locally: pnpm lint, pnpm typecheck, pnpm test, and pnpm exec tsc -p tsconfig.json --noEmit --noUnusedLocals --noUnusedParameters. Manual live NVIDIA smoke was skipped because no intentional NVIDIA_API_KEY was provided for this implementation pass.

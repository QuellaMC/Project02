MVP-005 Implementation

Date: 2026-05-16

What Changed

  • Implemented user-visible message projection in src/commit_effects/visible_reply.py.
  • Added commit_user_visible_message() to validate one normalized USER_MESSAGE, append one raw projection log, append one visible user message, and return a deterministic result.
  • Added user projection builders for user_visible_message, user_visible_message_committed, and user_visible_message_rejected.
  • Widened the existing VisibleConversationLog append typing to visible conversation records without adding a second append protocol or changing assistant visible-reply behavior.
  • Added focused unit and integration tests for the MVP-005 projection contract.
  • Review follow-up: added a direct top-level integration case proving unsupported source event type rejection through commit_user_visible_message().
  • Updated docs/plan/active-slice.html and docs/plan/index.html so they reflect the implemented state.

Why

MVP-004 can read recent visible messages through an injected source, but the runtime did not yet create a committed user-side visible transcript record. MVP-005 adds that write-side projection inside Commit and Effects while keeping concrete storage, orchestration, retrieval, model calls, and character state out of scope.

Review Notes

  • The implementation stays inside the existing Commit and Effects boundary and does not touch Runtime Kernel routing or Role Model Loop behavior.
  • The new user visible message uses a generated message_id and copies created_at, text, user ID, and conversation ID from the normalized source event.
  • Valid projection appends the raw user_visible_message_committed log before appending the visible user message.
  • Trusted source-event validation failures append user_visible_message_rejected and return a reject result; missing trusted identity still raises without logging.
  • Raw log and visible message snapshots are deep-copied so caller-side mutation cannot alter append-only truth.
  • No concrete ConversationLog storage, recent-message read source, idempotency policy, model call, or user-turn orchestrator was added.
  • Future-slice compatibility note: MVP-005 UserVisibleMessage includes kind and source, so a later visible-record-backed recent source must map to the narrower MVP-004 RecentVisibleMessage shape or deliberately widen that schema with tests.

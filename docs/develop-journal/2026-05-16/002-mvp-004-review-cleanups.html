MVP-004 Review Cleanups

Date: 2026-05-16

What Changed

  • Closed the recent-message time boundary: records with created_at greater than or equal to the current event timestamp now fail validation before adapter invocation.
  • Made render_role_model_input() reject non-empty recent_visible_messages when the context event has no non-empty conversation_id.
  • Replaced role-model and Commit and Effects local primitive validation helpers with the shared helpers from runtime.contracts, while keeping boundary-specific validation local.
  • Added unit and integration regression coverage for future/equal timestamp records and the missing conversation-id render path.
  • Updated the MVP-004 active spec to state the timestamp and conversation-id render validation rules.
  • Updated the plan index Mermaid graph so MVP-004 recent-message context is shown as implemented for the pull request.
  • Parked the shared RecentVisibleMessage contract idea for a later slice with a second consumer.

Why

Review found that a stale or buggy recent-message source could over-return records from after the current USER_MESSAGE, and a manually built context could render recent messages without a real conversation. Both cases could leak invalid context to the model, so MVP-004 now fails closed before model input rendering or adapter invocation.

2026-06-01 - MVP-022 Widened-Scope Spec Hardening

What Changed

  • Kept the widened MVP-022 scope that includes the existing INCIDENT_COMPLETION deterministic commit path.
  • Updated the active slice so the first concrete callers are runUserMessageTurn and the existing incident_completion_commit route.
  • Made runtime.kernel/deterministic_event_commit/INCIDENT_COMPLETION the only allowed caller tuple for incident.complete_from_event.
  • Replaced ambiguous operation names with component-prefixed operation names.
  • Resolved the logging open question: every registered operation gets operation envelope audit logs, while read/context payload snapshots are omitted and model input/output snapshots are not duplicated.
  • Expanded acceptance criteria and the test plan to cover the incident-completion event operation, cross-caller policy rejection, and operation audit redaction behavior.
  • Updated the implementation graph so RuntimeAccess also routes to the existing incident-completion event commit boundary.

Why

The wider scope is acceptable if the spec makes the second event family explicit. Notion 02A already defines INCIDENT_COMPLETION as a normalized runtime event and keeps operation routing internal to Runtime Kernel and Commit & Effects. Notion 08 requires enough raw-log evidence for replay and audit. The hardening keeps those constraints while avoiding a new scheduler, model call, external effect, storage adapter, or plugin API.

What Changed

  • Added shared CANCEL_INCIDENT_ACTION and cancel-specific life-action normalization in runtime.contracts.

  • Added commit_effects.incident_cancel to build cancel commit/finalize requests, re-read the active incident, match incident_id, build life_incident_cancelled logs, and reject failure cases without clearing state.
  • Extended InMemoryLifeIncidentStore with atomic cancel finalization: stage the success log through expose_committed_success_entry(), clear only the matching active scope, and keep copy-safe reads/results.
  • Wired runtime.user_turn with an explicit life_incident_cancel_finalizer opt-in that commits cancellation before the assistant visible reply.
  • Added focused unit and integration coverage for contract parsing, Role Model input rendering, cancel commit/finalizer behavior, store scope isolation, raw-log query visibility, no-active rejection, and incident-ID mismatch rejection.

Review Notes

  • Cancellation remains explicitly opted in; default visible-reply, state-patch, and incident-start turns keep their existing behavior.
  • The cancel boundary uses the existing active-incident request/read validators and does not add interruption, completion, resume, go-idle, queue, scheduler, body, Live2D, retrieval, or database behavior.
  • life_incident_cancelled is an atomic finalizer success kind, so the success log must be staged and confirmed before it is query-visible.
  • Rejected cancel attempts append life_incident_cancel_rejected through the ordinary raw-log path and leave the active incident unchanged.
  • Active slice scope did not change during implementation.

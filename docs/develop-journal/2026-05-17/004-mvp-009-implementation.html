What Changed

  • Added shared runtime contract helpers for normalize_living_state_patch(), normalize_role_model_turn_result(), and visible replies with an optional living-state patch.
  • Extended the Role Model Loop so state-patch support is opt-in, state-aware instructions render only for opted-in calls, and malformed or disallowed patches fail as model-output parse errors.
  • Added commit_effects.living_state as the MVP-009 Commit and Effects boundary for injected living-state patch commits, skips, rejections, and raw log entries.
  • Wired run_user_message_turn() to opt in only when both current-state read and patch-write boundaries are present, stop on patch rejection, and project a visible-reply-only result before assistant reply commit.
  • Kept commit_visible_reply() strict by moving only the shared envelope validation into runtime.contracts; it still rejects decisions carrying state_patch unless user-turn projection strips the patch first.

Why It Was Needed

MVP-008 proved the read-only living_state_brief in DecisionContext. MVP-009 takes the next narrow Phase 2 step: the model may propose one optional state_patch.living_state, while Commit and Effects owns validation, runtime-owned metadata, raw logs, and the injected write boundary.

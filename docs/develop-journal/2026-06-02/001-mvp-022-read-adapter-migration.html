2026-06-02 - MVP-022 Read Adapter Migration

What Changed

  • Added built-in read operations for character_state.read_current, incident_lifecycle.read_active, and incident_lifecycle.read_interrupted.
  • Changed runUserMessageTurn so role-model context reads for current state, active incident, and interrupted incident go through RuntimeAccess operation-backed source wrappers.
  • Kept the domain modules as owners: the new operations delegate to existing source contracts and reuse existing Character State Engine request/snapshot validators instead of duplicating schema rules.
  • Added focused user-turn coverage for operation audit records, malformed current-state output rejection before model calls, and reviewed runtimeComponents user-turn actions that contribute context sources.
  • Updated the active slice so MVP-022 documents this adapter migration as part of the component-registry robustness follow-up.

Why

MVP-022 already routed recent-message reads and context sections through registered operations. Current state and incident reads were still passed directly into the Role Model Loop from the user-turn orchestrator. This follow-up removes that production bypass while keeping the migration adapter-only: runtime orchestration calls RuntimeAccess, the built-in operation delegates, and the Character State Engine or incident source remains the behavior owner.

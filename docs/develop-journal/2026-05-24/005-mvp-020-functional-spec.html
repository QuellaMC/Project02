Why It Was Needed

Notion describes user messages as interruptions of active life incidents, but the durable interrupted/background/resume flow is broader than the next safe implementation step. MVP-020 records the smallest useful slice: Character State Engine computes a read-only user_message_interrupted_active_incident cue in the existing user-turn context whenever the same context already includes a valid active_incident.

Scope Review

  • Active slice scope changed from MVP-019 to MVP-020.
  • No production code was changed in this planning pass.
  • The proposed schema change is model-facing only: one optional presence flag inside DecisionContext.character_snapshot.
  • The spec explicitly forbids durable interrupted status, interrupted_incident, resume/go-idle/no-change actions, Commit & Effects transitions, scheduler/body/Live2D work, and Runtime Kernel route-policy changes.
  • The implementation path must reuse the existing active-incident brief read and Role Model Loop validation seam.

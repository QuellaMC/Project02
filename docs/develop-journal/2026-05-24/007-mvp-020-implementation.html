2026-05-24 - MVP-020 Implementation

Implemented MVP-020 - Computed User Interruption Context v0.1 on branch feature/mvp-020-computed-user-interruption-context.

What Changed

  • Added shared contract constant USER_MESSAGE_INTERRUPTED_ACTIVE_INCIDENT_FIELD for the new model-facing field name.
  • Updated Character State Engine context construction to set character_snapshot.user_message_interrupted_active_incident = true only when the existing active-incident read returns a valid active incident brief.
  • Updated Role Model Loop character-snapshot validation to accept the field, require literal true, require a sibling active_incident, and continue rejecting unrelated future fields.
  • Added unit and integration coverage proving the flag is derived from the single existing active-incident read, omitted without an active incident, rendered to the model input, copied into the success log, and does not change allowed actions.

Why It Was Needed

Notion describes user messages as interruptions of active life incidents, but durable interrupted/background/resume policy is a larger later slice. MVP-020 gives the Role Model Loop a precise read-only cue without changing runtime routing, Commit & Effects behavior, incident storage, scheduler behavior, body state, Live2D state, or visible output delivery.

Shared Code And Refactor Review

  • The implementation reuses build_active_incident_request(), build_active_incident_brief(), validate_active_incident_brief_for_event(), and the existing Role Model Loop DecisionContext.character_snapshot validation path.
  • No second active-incident read, new active-incident source, new Kernel policy helper, new log kind, or new Commit & Effects boundary was added.
  • The only refactor made was promoting the new field name to the shared runtime.contracts layer so Character State Engine and Role Model Loop do not duplicate a string literal.
  • Higher-level refactor proposal: if the next interruption slice adds interrupted_incident, durable status changes, or more computed character-snapshot fields, promote a shared character-snapshot schema validator into runtime.contracts. MVP-020 is too small to justify that extraction by itself.

Scope Review

  • Active slice scope did not widen during implementation.
  • No durable interrupted status, interrupted_incident object, resume/go-idle/no-change action, scheduler behavior, body effect, Live2D effect, raw-log kind, or visible output behavior was added.
  • The field remains a presence flag: it is omitted when no active incident is in the same user-message context and is never emitted as false.

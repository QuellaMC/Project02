MVP-001 Future Compatibility Review

Date: 2026-05-15

What Changed

  • Updated src/runtime/kernel.py so normalized events preserve the validated input event type instead of restamping the current constant.
  • Replaced the logged-only route helper with route_runtime_event, which copies event_type from RuntimeEvent.type.
  • Added an event-route registry so model_needed and next_step come from an event-specific route policy instead of a universal fallback.
  • Kept accepted runtime behavior limited to USER_MESSAGE; unsupported event types still fail before logging.
  • Added a payload-normalizer registry containing only the implemented USER_MESSAGE case.
  • Added a focused route regression test in tests/unit/test_runtime_kernel.py.
  • Updated AGENTS.md with future-compatible implementation guidance that does not permit speculative behavior.
  • Clarified docs/plan/active-slice.html so route output is derived from the normalized event record.

Why It Changed

The first implementation hard-coded USER_MESSAGE in route output. That matched MVP-001 behavior, but it would force a contract-level edit when a later reviewed slice adds another event type. This pass keeps today's behavior unchanged while making the existing route result depend on the normalized runtime record and the registered route policy for that event type.

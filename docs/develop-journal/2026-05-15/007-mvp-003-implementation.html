MVP-003 Implementation

Date: 2026-05-15

What Changed

  • Added the commit_effects.visible_reply module for the first Commit and Effects Engine behavior.
  • Added VisibleConversationLog as an injected append-only protocol for internal visible output records.
  • Implemented visible reply commit validation, visible output construction, committed raw log construction, rejected raw log construction, and the commit_visible_reply() flow.
  • Added unit tests for output building, validation failures, committed/rejected raw log snapshots, and rejection failure-code validation.
  • Added integration tests for successful visible output commit and invalid decision rejection.
  • Updated the active plan and plan index to show MVP-003 is implemented and tested, pending review.

Why

MVP-002 produced a parsed visible_reply decision and intentionally stopped before committing any visible output. MVP-003 closes that next smallest boundary by validating the model proposal, appending one internal visible output, and recording the commit or rejection in the raw event log.

Review Notes

  • The slice scope did not expand beyond the active MVP-003 spec.
  • The implementation uses injected append interfaces only; there is no concrete database, transaction manager, UI delivery, external service, scheduler, or worker.
  • Successful commits append the visible output before appending visible_reply_committed, so visible append failure does not create a false committed raw log.
  • Supported validation failures with trustworthy source identity append visible_reply_rejected and return a rejected result without visible output.
  • Malformed source identity raises before rejection logging because there is no reliable trace/event envelope.
  • The visible output and raw log snapshots are deep-copied to preserve append-only in-memory truth.

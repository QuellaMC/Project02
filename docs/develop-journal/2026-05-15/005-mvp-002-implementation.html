MVP-002 Implementation

Date: 2026-05-15

What Changed

  • Added the role_model.loop module for the MVP-002 Role Model Loop boundary.
  • Added minimal DecisionContext construction for a normalized USER_MESSAGE.
  • Added deterministic RoleModelInput rendering with a narrow visible-reply instruction contract.
  • Added an injected fake-adapter protocol with no live provider, network, API key, retry, or streaming behavior.
  • Added strict JSON parsing for visible_reply-only CharacterDecision output.
  • Added success and failure raw log entries for role-model turns.
  • Added focused unit and integration tests for the implemented role-model path.
  • Updated the active plan and plan index to show MVP-002 is implemented and tested, pending review.

Why It Changed

MVP-001 proved runtime intake, ID normalization, and raw event logging without model calls. MVP-002 adds the smallest model-call boundary that can render current-event context, call a fake adapter, parse a visible reply decision, and record the turn while leaving durable commit behavior to a later slice.

Review Notes

  • The Role Model Loop is standalone for this slice; RuntimeKernel behavior and MVP-001 tests remain unchanged.
  • The parser rejects extra output fields, unsupported schema versions, unknown actions, missing visible_reply, and empty reply text.
  • CharacterDecision parsing and completed-log validation share the same canonical normalizer so reply text trimming cannot diverge between paths.
  • Runtime and role-model raw log entries now use a shared runtime.logging.build_raw_log_entry() helper for the common envelope and snapshot copy.
  • Downstream event type fields are derived from the validated normalized event rather than duplicating the current USER_MESSAGE literal.
  • render_role_model_input() validates the required nested DecisionContext.event fields and rejects unsupported extra context fields before rendering a model input.
  • Optional normalized payload strings, such as user_id and conversation_id, are preserved even when empty so the role-model boundary accepts the MVP-001 normalized event contract.
  • The adapter receives a deep-copied model input so adapter-side mutation cannot corrupt the rendered input snapshot later written to the raw log.
  • Completed and failed raw log entries deep-copy their snapshots so caller-side mutation cannot change append-only in-memory log truth.
  • Malformed adapter-output envelopes still produce a failure log, but invalid envelopes are stored under raw_model_output_snapshot instead of model_output.
  • Role-model log builders validate completed decisions, failure stages, and failure codes before returning appendable raw-log records.
  • Adapter exceptions and malformed outputs append role_model_turn_failed; successful parses append role_model_turn_completed.
  • The parsed decision is returned for a future Commit and Effects slice. It is not persisted as a visible reply in MVP-002.
  • No new future ideas appeared during implementation beyond the commit, history, provider, and state ideas already parked in future-slices.html.

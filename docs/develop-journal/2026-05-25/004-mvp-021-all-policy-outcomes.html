2026-05-25 - MVP-021 All Policy Outcomes

Updated MVP-021 - Minimal Durable User Interruption Boundary v0.1 after deciding the slice should cover all three existing interrupt_policy values without adding post-turn lifecycle behavior.

What Changed

  • Changed the goal from interruptible-only interruption to a deterministic three-policy outcome boundary.
  • Kept interrupt_policy = "interruptible" as the only path that moves state from active_incident to interrupted_incident.
  • Added life_incident_continued_in_background for interrupt_policy = "background"; the active incident remains unchanged.
  • Added life_incident_protected_from_interruption for interrupt_policy = "protected"; the active incident remains unchanged.
  • Updated requirements, acceptance criteria, test plan, implementation notes, and future-slices wording to keep resume/go-idle/no-change and durable background/protected state out of MVP-021.

Why It Was Needed

Covering all three policy values avoids another immediate follow-up slice while still preserving the narrow boundary: only interruptible changes incident state, and the other two policies produce query-visible raw-log facts without scheduler, body, Live2D, proactive output, or post-turn action behavior.

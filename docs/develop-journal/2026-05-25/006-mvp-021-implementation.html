2026-05-25 - MVP-021 Implementation

Implemented MVP-021 - Minimal Durable User Interruption Boundary v0.1 on feature/mvp-021-minimal-durable-user-interruption-boundary. The slice follows the checked Notion source pages for Runtime Kernel interruption policy, Role Model Loop compact context, living incident lifecycle, Character State Engine context ownership, and raw logging.

What Changed

  • Added a deterministic Commit & Effects interruption boundary for normalized USER_MESSAGE events.
  • For interrupt_policy = "interruptible", the boundary writes a query-visible life_incident_interrupted success log through the existing atomic finalizer visibility pattern, then moves the scoped active incident into one interrupted slot.
  • For "background" and "protected", the boundary appends query-visible policy logs and leaves the active incident unchanged.
  • Extended InMemoryLifeIncidentStore with the interrupted read/finalizer surface while preserving the existing active read, cancel, complete, and start behavior.
  • Added an interrupted_incident Character State Engine brief and Role Model Loop validation/rendering, without adding resume/go-idle/no-change actions.
  • Wired the optional user-turn interruption dependency so the deterministic policy outcome runs before model context build when explicitly supplied.
  • Review follow-up: tightened user-turn integration coverage so both non-interruptible policies, "background" and "protected", prove the policy log is written before model context while the active incident remains available.

Review Notes

  • The implementation reuses existing lifecycle helpers, raw-log entry construction, atomic success visibility confirmation/discard, active-incident request scope, and in-memory store scope helpers.
  • No new RuntimeEvent family, scheduler, body, Live2D, retrieval, tool, concrete database, proactive output, or durable background/protected status was added.
  • Higher-level refactor proposal: the deterministic interrupt path exposes a small future seam for sharing more lifecycle finalizer staging code, but the current extraction should wait until another deterministic lifecycle path needs it.

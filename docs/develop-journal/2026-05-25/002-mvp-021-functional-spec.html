Why It Was Needed

MVP-020 proved a read-only model-context cue for user interruption. Notion's Runtime Kernel, Living State, and Runtime Logging pages call for the durable lifecycle transition where a user message interrupts an active incident and the raw log can show active -> interrupted. MVP-021 keeps that next step narrow: one deterministic Commit & Effects transition, one life_incident_interrupted raw log, and one interrupted-incident context read.

Scope Review

  • Active slice scope changed from MVP-020 to MVP-021.
  • No production code was changed in this planning pass.
  • The proposed storage change is in-memory only: one latest interrupted incident per existing incident scope.
  • The spec explicitly forbids resume/go-idle/no-change actions, background/protected policy expansion, scheduler/body/Live2D/tool/retrieval behavior, proactive output, concrete persistence, and broad Runtime Kernel routing changes.
  • The implementation path must reuse existing active-incident reads, lifecycle raw-log/finalizer patterns, and Character State Engine context validation instead of creating parallel incident lifecycle code.

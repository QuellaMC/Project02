2026-05-23 - MVP-018 Shared Lifecycle Helper

Addressed the MVP-018 implementation review finding that the new complete boundary copied too much of the existing cancel commit pipeline.

What Changed

  • Added commit_effects.incident_lifecycle as the narrow shared helper for active-incident lifecycle commit orchestration.
  • Moved the common cancel/complete flow for commit time assignment, success log staging, finalizer result validation, raw-log visibility confirmation, post-confirm completion, rejection logging, and success/rejection result shaping into that helper.
  • Moved the remaining mechanical private validation wrappers for source events, role-model results, active-incident reads, finalizer result envelopes, committed log entries, failure envelopes, raw-log guard lookup, matching incident fields, source-event IDs, contract-error wrapping, and snapshot copying into the same shared lifecycle helper.
  • Kept subtype-specific request parsing, life-action normalization, active-incident read wrapping, snapshot construction, success log schemas, finalize request validation, failure-code tables, and public exception types in incident_cancel and incident_complete.
  • Preserved the public entry points, schema names, statuses, raw-log kinds, failure stages, failure codes, and existing tests for both cancel and complete.
  • Updated the active slice review notes to record that the documented duplication risk is now resolved by the shared helper.

Why It Was Needed

The active slice explicitly called out duplication between cancel and complete as the main implementation risk. The shared helper removes the duplicated atomic finalizer and visibility pipeline without introducing a generic incident history store, extra lifecycle actions, or future-slice behavior.

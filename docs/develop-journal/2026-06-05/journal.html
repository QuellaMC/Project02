MVP-004 Storage Contract Review Follow-Up

Addressed review findings around partial local stores and exported file-backed log access. The durable chat path now fails loudly when existing store content is missing its schema marker, and a store with existing session directories no longer treats a missing session catalog as an empty catalog. The file-backed runtime log store now validates the versioned schema, session catalog, and selected session directory before every read or append.

  • Added CLI regressions for orphaned default-session logs with a missing schema marker or missing session catalog.
  • Moved reusable session-readability validation into src/session-store.ts and reused it from src/file-runtime-log-store.ts.
  • Added a file-log-store regression proving uncataloged sessions cannot create orphan log files through the exported API.
  • Added inspect coverage proving rejected turns persist rejection evidence without fake visible messages.
  • Left unsupported extra-key rejection as a watch item; the current decoders continue to canonicalize known fields for this slice.

MVP-004 Conversation Evidence Hardening

Tightened the read-side file log invariants after a repro showed that raw events referencing visible message IDs could coexist with an empty or incomplete conversation.jsonl. Public log reads now fail if trace, raw-event, and conversation evidence disagree, while append-time reads remain permissive enough for the existing write order of an in-progress turn.

  • Added regressions for empty and incomplete conversation logs when raw events reference visible messages.
  • Added regressions for missing trace or raw-event logs when other session evidence already exists.
  • Added a regression for complete-looking conversation records that lack terminal raw-event evidence.
  • Kept the validation inside src/file-runtime-log-store.ts so chat resume and inspect share the same corruption checks.

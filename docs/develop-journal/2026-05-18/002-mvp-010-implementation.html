2026-05-18 - MVP-010 Implementation

What Changed

  • Added the MVP-010 LivingStatePatchFinalizer protocol, finalize request/result shapes, finalize error, and centralized living_state_patch_finalize failure stage.
  • Changed successful living-state patch commits so Commit and Effects still uses the MVP-009 prepare/snapshot-candidate path, validates the candidate, builds the living_state_patch_committed raw log entry, then sends the snapshot and log entry together through finalize_living_state_patch_commit().
  • Kept ordinary rejection logs on the existing raw-log fake for validation, store, and finalizer failures.
  • Updated run_user_message_turn() so state-patch opt-in now requires a current-state source, the MVP-009 prepare store, and the MVP-010 atomic finalizer.
  • Added unit and integration fakes that expose separate durable state snapshots and durable success raw logs, proving all-or-nothing success visibility without concrete storage.

Why It Was Needed

MVP-009 validated one optional living-state patch and produced a committed snapshot candidate, but success still exposed the state candidate and success raw log through separate steps. MVP-010 narrows the next runtime contract to one injected atomic finalization boundary before adding any concrete CharacterRuntimeStateStore.

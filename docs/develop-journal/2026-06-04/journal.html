Post-Review Transcript Boundary Fix

A review agent found that session.visibleTranscript exposed the same mutable array used by the conversation core. The core now keeps its mutable transcript private, exposes frozen transcript snapshots, freezes committed visible messages, and validates malformed character agent reply shapes as reply validation failures before committing a turn.

  • Added a regression proving external callers cannot push fake transcript entries or rewrite committed messages.
  • Added a regression proving malformed agent replies reject as CharacterReplyValidationError with no partial transcript commit.
  • Re-ran focused conversation, chat, relay tests plus the full repo gates.

Second Review Character Identity Fix

A later review found that a character agent could mutate the live character profile object during turn generation and affect committed character metadata. The core now freezes the built-in character profile, copies and freezes custom character profiles when sessions are created, freezes the session object, and passes only frozen character identity to agents.

  • Added a regression proving agent-side character mutation cannot change committed speaker metadata.
  • Confirmed the local chat and relay contracts still pass after the identity hardening.

PR Review Same-Session Turn Serialization Fix

A PR review found that concurrent calls to runCharacterTurn() for the same session could read the same pre-commit transcript and commit in reply-resolution order instead of call order. The conversation core now serializes the full turn pipeline per session before reading recent context, calling the agent, validating the reply, and committing visible messages.

  • Added a regression with two deferred async agent replies that resolve out of order.
  • Confirmed the second queued turn sees the first committed turn as recent visible context.
  • Confirmed failed turns still leave the queue available for later turns.

MVP-003 Runtime Event Trace Integrated

Integrated the MVP-003 child task work into the local chat path. Each non-exit chat input now reserves runtime identity, becomes a validated USER_MESSAGE event when valid, runs through the local runtime adapter, and records in-memory trace, raw event, and visible conversation log records while preserving default chat output.

  • Added src/runtime-event.ts for USER_MESSAGE event identity, normalized payload, deterministic identity injection, and rejected-intake errors carrying reserved identity.
  • Added src/runtime-log.ts for append-only in-memory runtime trace, raw event, and conversation log snapshots.
  • Added src/local-runtime.ts so runtime handling reuses runCharacterTurn() instead of duplicating conversation logic.
  • Updated src/chat-cli.ts so default chat still prints the MVP-002 transcript while --trace emits one JSON Line per processed input to stderr.
  • Added focused runtime event, runtime log, local runtime adapter, and chat trace-mode tests while keeping relay compatibility covered.

Integration decisions:

  • Invalid user input rejected during event construction uses the reserved identity on RuntimeEventInputError and the shared local-runtime rejection helper, so the CLI does not maintain a parallel log contract.
  • Intermediate raw records such as receipt, normalization, and visible commit do not claim a final status; rejected validation records and final completed/rejected outcomes carry status.
  • /exit remains a CLI command, not a runtime event, and therefore emits no trace summary.

Addressed the consistency caveat that the MVP-003 raw event records were named like the Notion RawEventLog boundary but only stored identity, kind, status, reason, and visible message IDs. Raw event records now carry an immutable payload summary, preserving raw CLI input when available and the normalized USER_MESSAGE payload details for runtime-handled events.

  • Added RawEventLogPayloadSummary to the runtime log contract and centralized copy/freeze behavior in the log store.
  • Threaded raw CLI input into accepted and rejected local runtime paths without changing user-facing chat output.
  • Updated the active slice to clarify that this MVP implements an in-memory raw-log-shaped boundary, not the full lossless Notion RawEventLog retention model.
  • Added regressions proving payload summaries are stored with raw records and frozen as append-time snapshots.

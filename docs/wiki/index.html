Architecture Summary

"All triggers become RuntimeEvents."

The project is organized around one universal event path and four core runtime modules:

  1. Runtime Kernel: event intake, normalization, trace IDs, priority, interruption, scheduling, policy, and routing.
  2. Character State Engine: current character reality, living state, virtual body, incidents, directives, continuity, retrieval planning, and DecisionContext building.
  3. Role Model Loop: model input rendering, model call, structured CharacterDecision parsing, and output contract enforcement.
  4. Commit and Effects Engine: validation, durable commits, raw logging, tool execution, visible/proactive messages, Live2D status, assets, and future events.

Local Development Contract

  • Choose one small part from the Notion roadmap per development pass.
  • Write or update the local HTML functional spec before writing runtime code.
  • Review the spec and implementation for reuse, duplication, unused code, security, efficiency, and future compatibility.
  • Use TDD: write the smallest unit and integration tests that prove the behavior, then implement the minimum production code.
  • Do not add module folders until a slice needs code in that module.
  • Prefer shared code only when at least two concrete callers or a clear boundary justify it.

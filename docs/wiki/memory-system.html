Project02 Memory System

A character has three ways to know something that happened before this turn, and each lives in its own layer with its own trust story: a tiny curated memory that is always in the prompt, session history it can search on demand, and at most one external retrieval-driven provider running alongside them.

The model curates and proposes; the runtime validates, caps, and commits. No layer lets raw model output or foreign plugin content write the trusted prompt directly.

Curated memory

The character-memory package keeps two capped stores per character: character notes and a user profile. The whole store is injected every session as a Curated memory block with capacity headers, so the character never has to search for what it must always know. The snapshot is frozen per launch: writes land on disk immediately and reach the prompt at the next launch, keeping the prompt prefix byte-stable for provider caching.

The model maintains the store through one atomic tool, memory.update: add appends an entry, replace and remove select exactly one existing entry by a unique old_text substring, and a batch either fully commits or fully rejects. Capacity overflows reject with usage numbers so the model compresses or prunes instead of silently losing entries. There is no read tool and no automatic extraction.

Session search

Everything said in past sessions is recorded and indexed; the character recovers exact conversations with sessions.search and sessions.read. Curated memory holds what must always be known; session search recovers what was merely said. A fact worth keeping gets promoted by the model from a transcript into memory.update.

External providers

Retrieval-driven long-term memory rides the memory_provider plugin kind: per-turn recall items enter the untrusted plugin frame (source-referenced, bounded, budget-capped), turns are captured for backend-side extraction, and a provider exposes whichever namespaced tools its backend supports — see the table below, since the compat packages expose fewer than mem0 does. Providers are disabled by default; enable one and, when several are enabled, select it with pnpm runtime-config default-memory-provider <pluginId>. Activation keeps at most one selected, so by default an external provider runs alongside curated memory rather than replacing it; an operator who explicitly disables character-memory can run a provider on its own.

Package Backend Notes
mem0 Mem0 platform API or a self-hosted Mem0 server REST via fetch; secret key from MEM0_API_KEY; capture lets the backend extract, mem0.add stores verbatim.
openclaw-compat An OpenClaw context-engine plugin module Pinned interface v1: assembly becomes recall, turns are ingested. No tools — the engine surface has no row-backed search or add.
hermes-compat A Hermes memory-provider module (JS binding) Pinned interface v1: prefetch/syncTurn/search/shutdown. One tool, hermes-compat.search; no add tool.

Trust model

Curated memory renders in a trusted prompt frame because the runtime owns every step: entries are validated and capped at write time, sections are typed and screened at render time, and the curated_context access that feeds the frame is granted only to bundled packages by catalog provenance — a manifest flag alone never earns it. External provider content stays in the untrusted plugin frame under the shared token budget, and recall items without source references are dropped rather than shown.

Compat packages import the module the operator configures, which executes operator-trusted code — the same trust an installed operator package already gets. Both compat surfaces are version-pinned: when the foreign interface moves, construction fails with the exact mismatch instead of guessing.

Picking a setup

Want Do
Characters that remember preferences and facts out of the box Nothing — curated memory and session search are on by default.
Large semantic long-term memory Enable mem0 and set MEM0_API_KEY; for a self-hosted server set backend to server and baseUrl to its origin, where the key is then optional.
Reuse a memory plugin from another ecosystem Enable the matching compat package and set its modulePath to an absolute path.

MVP-003 - Minimal Visible Reply Commit

Status: completed, implemented, and tested

Created: 2026-05-15. Implemented: 2026-05-15. Completed slice path: docs/plan/completed/mvp-003-minimal-visible-reply-commit.html. Runtime language: Python 3. Test runner: Python standard library unittest.

Source Context

Product direction comes from the Notion project hub Live Character Framework. The relevant source pages are 02 - Runtime Architecture, 08 - Runtime Logging & Trace, and 09 - MVP Roadmap & Open Questions.

Current direction: the model proposes a structured CharacterDecision; Commit and Effects validates what the runtime accepts, commits durable effects, and records the result in the raw log.

Local implementation truth comes from MVP-001 and MVP-002. MVP-002 parses a visible_reply-only decision and returns status = "decision_ready_for_commit"; MVP-003 is the first Commit and Effects slice that accepts that result.

Goal

Add the smallest Commit and Effects Engine behavior after MVP-002: accept a parsed visible-reply decision plus the normalized source USER_MESSAGE, validate that the decision belongs to that event, append one visible conversation output through an injected interface, append one raw commit log entry, and return a deterministic commit result. Invalid decisions with trustworthy trace identity are rejected through a raw log entry and do not create visible output.

Implemented Scope

  • One source event type: normalized USER_MESSAGE from MVP-001.
  • One model-turn result status: decision_ready_for_commit from MVP-002.
  • One accepted decision action: visible_reply.
  • One visible output kind: assistant_visible_reply.
  • One injected append-only VisibleConversationLog interface for committed output.
  • One accepted raw log kind: visible_reply_committed.
  • One rejected raw log kind: visible_reply_rejected.
  • Shared contract helpers for normalized USER_MESSAGE and visible-reply decisions.

Explicit Non-Goals Preserved

  • No live model provider call or Role Model Loop behavior change.
  • No full user-turn orchestrator through RuntimeKernel.
  • No real UI delivery, push notification, streaming, network call, or external side effect.
  • No concrete database adapter, migration, transaction manager, or delivery outbox.
  • No conversation history retrieval or recent messages in DecisionContext.
  • No character state, living state, incidents, tools, retrieval, Live2D, assets, scheduler, compaction, or replay UI.

Minimal Schema Added

VisibleConversationOutput

type VisibleConversationOutput = {
  output_id: string
  trace_id: string
  source_event_id: string
  kind: "assistant_visible_reply"
  created_at: string
  schema_version: "0.1"
  text: string
  user_id?: string
  conversation_id?: string
  source: {
    decision_action: "visible_reply"
    role_model_status: "decision_ready_for_commit"
  }
}

Commit Log Entries

type VisibleReplyCommittedLogEntry = {
  kind: "visible_reply_committed"
  trace_id: string
  event_id: string
  schema_version: "0.1"
  data: {
    source_event: RuntimeEvent
    role_model_result: RoleModelTurnResult
    output: VisibleConversationOutput
  }
}

type VisibleReplyRejectedLogEntry = {
  kind: "visible_reply_rejected"
  trace_id: string
  event_id: string
  schema_version: "0.1"
  data: {
    source_event: unknown
    role_model_result_snapshot: unknown
    decision_snapshot?: unknown
    failure: {
      stage: "commit_validation"
      code: string
      message: string
    }
  }
}

Acceptance Evidence

Criterion Evidence
Valid visible-reply result commits one visible output. commit_effects.visible_reply.commit_visible_reply() and integration coverage.
Valid commit appends one visible_reply_committed raw log entry. Unit and integration tests assert the committed log envelope.
Unsupported status/action, empty reply text, or identity mismatch rejects without visible output. Unit and integration tests assert reject results and no output append.
Supported rejection appends one visible_reply_rejected raw log entry. Reject-path tests assert the raw log kind and failure payload.
No live model provider, external service, UI delivery, or concrete database is called. Implementation uses injected in-memory test boundaries only.

Post-Code Review Notes

  • The new Commit and Effects module validates before appending visible output.
  • The raw committed log is appended before visible output so raw-log storage failure cannot leave an unlogged visible side effect.
  • Rejected logs preserve raw source-event snapshots for audit and replay, but public reject results remain within the implemented USER_MESSAGE result schema.
  • Deep copies protect in-memory append-only truth from caller-side mutation.
  • The shared status constant and visible-reply contract helper reduce drift without adding a broader turn-result validator.
  • The slice stayed below the full user-turn loop; MVP-004 may now add recent visible messages to the context builder without changing commit behavior.

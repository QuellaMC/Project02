Source Context

Product direction comes from the Notion project hub Live Character Framework. The source pages checked for this slice are 02 - Runtime Architecture, 03 - Role Model Loop & Decision Contract, 03 - Role Model Interface & Prompting, 05 - Living State & Scheduled Life, 06 - Character State Engine & Retrieval Management, and 09 - MVP Roadmap & Open Questions.

Notion separates a top-level RoleModelInputEnvelope from a compact DecisionContext. The current implementation still carries call_type, current event, and allowed_actions inside DecisionContext. MVP-015 preserved that shape intentionally while moving context assembly behind character.state.context. MVP-016 is the smallest schema split that removes only those envelope-owned fields from the inner context.

Source-context mismatch to record before implementation: Notion 03 - Role Model Loop & Decision Contract and 06 - Character State Engine & Retrieval Management define the newer split where current event data and allowed actions live outside compact DecisionContext. Notion 02 - Runtime Architecture and 05 - Living State & Scheduled Life still include broader DecisionContext examples with call_type, event, and allowed_actions. MVP-016 follows the newer Role Model/Character State split and treats the broad examples as older or conceptual lifecycle examples until later private-call and lifecycle slices reconcile those shapes.

Local implementation truth comes from completed MVP-001, MVP-002, MVP-004, MVP-006, MVP-007, MVP-008, MVP-011, MVP-012, MVP-014, and MVP-015.

Goal

Introduce a narrow RoleModelInputEnvelope boundary so Role Model Loop owns call metadata, current event data, allowed action policy, and instructions, while Character State Engine returns an inner compact DecisionContext that contains only the current character snapshot for this USER_MESSAGE call.

Current Scope

  • One implemented event family remains in scope: USER_MESSAGE.
  • One call type remains in scope: user_message_visible_reply.
  • One model input envelope is in scope: RoleModelInputEnvelope for the existing user-message role-model call.
  • The inner DecisionContext keeps only schema_version, trace identity, event identity, and character_snapshot.
  • The outer envelope owns call_type, current event, allowed_actions, and the existing instruction string selected from those allowed actions.
  • The Character State Engine context builder continues to own recent visible messages, living-state brief, and active-incident brief source orchestration.
  • Role Model Loop continues to own input rendering/validation, adapter invocation, structured output parsing, and role-model turn logs.

Explicit Non-Goals

  • No new event family, no new call type, and no private role-model call.
  • No new decision action, allowed-action combination, prompt instruction text, model provider, adapter behavior, or parser behavior.
  • No rename from the existing instructions field to an output_contract field in this slice.
  • No retrieval planner, Unified Retrieval Index, context.retrieve(), semantic search, keyword search, exact source expansion, active threads, body state, scheduled directives, interrupted incidents, completed incidents, or runtime notes.
  • No dedicated context-build raw log kind, model I/O store, replay/debug UI, concrete database storage, migration, scheduler, tool, asset, Live2D, or external side effect.
  • No change to run_user_message_turn() ordering, visible conversation projection, living-state patch commit behavior, or incident-start commit behavior.

Minimal Schema

DecisionContext

type DecisionContext = {
  schema_version: "0.1"
  trace_id: string
  event_id: string
  character_snapshot: {
    recent_visible_messages: RecentVisibleMessage[]
    living_state_brief?: LivingStateBrief
    active_incident?: ActiveIncidentBrief
  }
}

The split intentionally removes call_type, current event, and allowed_actions from the inner context. Trace and event identity remain for validation and log correlation.

RoleModelInputEnvelope

type RoleModelInputEnvelope = {
  schema_version: "0.1"
  trace_id: string
  event_id: string
  call_type: "user_message_visible_reply"
  event: {
    type: "USER_MESSAGE"
    text: string
    created_at: string
    user_id?: string
    conversation_id?: string
  }
  allowed_actions:
    | ["visible_reply"]
    | ["visible_reply", "state_patch"]
    | ["visible_reply", "life_action"]
  instructions: string
  decision_context: DecisionContext
}

The envelope is the model input shape passed to the adapter. It keeps the existing top-level schema_version, trace_id, event_id, and instructions values, while moving call_type, event, and allowed_actions out of DecisionContext.

Character Context Builder Request

type CharacterContextBuilderRequest = {
  schema_version: "0.1"
  event: RuntimeEvent<"USER_MESSAGE">
  recent_visible_messages_source?: RecentVisibleMessagesSource
  current_state_source?: CurrentCharacterStateSource
  active_incident_source?: ActiveIncidentSource
}

The Character State Engine builder should not need write-action opt-in flags after this split. It builds compact character context; Role Model Loop owns allowed action policy.

Implementation Boundaries

  • character.state.context owns compact DecisionContext construction and source orchestration only.
  • role_model.loop owns RoleModelInputEnvelope construction, input validation, instruction selection, adapter invocation, output parsing, and role-model logging.
  • Shared-code ownership is explicit for this slice: runtime.contracts remains the source for normalized USER_MESSAGE validation and action constants; character.state.context remains the source for current context-builder source checks; and role_model.loop remains the source for current model input validation and allowed-action instruction helpers unless the implementation extracts a smaller shared helper with tests.
  • runtime.user_turn remains responsible for orchestration order and source injection; it should not learn envelope field rules beyond passing current arguments.
  • runtime.contracts should only change if an existing shared validator or action constant needs to be reused; do not add speculative future schema helpers.
  • Commit and Effects modules should not change unless tests need to follow the updated model input envelope validation path.

Review Notes

  • This is a schema-ownership split, not a behavior expansion.
  • The source-context mismatch above is intentional for MVP-016: newer Role Model and Character State pages control the envelope/context split, while broader DecisionContext examples in Runtime Architecture and Living State pages remain deferred conceptual lifecycle examples.
  • The highest risk is accidentally changing model-call semantics while moving fields. Tests should compare event values, allowed actions, instructions, character snapshot values, parser permissions, and log kinds.
  • The main duplication risk is reimplementing existing validation while moving fields; implementation review must check that the exact FR-13 surfaces were reused, moved, extracted, or compatibility-exported rather than copied.
  • Keep the split minimal: move only call_type, event, and allowed_actions out of DecisionContext.
  • Do not add Notion's broader private-call envelope fields until a private-call slice exists.
  • Do not add an output_contract field in this slice; the current instruction strings already carry the active output contract.
  • Preserve the model input snapshot in raw logs as the auditable place where the envelope and compact context can be inspected.

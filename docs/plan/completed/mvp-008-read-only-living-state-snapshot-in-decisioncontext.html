MVP-008 - Read-Only Living State Snapshot in DecisionContext

Status: completed, implemented, and tested; PR #8

Created: 2026-05-16. Implemented: 2026-05-17. Completed archive path: docs/plan/completed/mvp-008-read-only-living-state-snapshot-in-decisioncontext.html. Runtime language: Python 3. Test runner: Python standard library unittest. Branch: feature/mvp-008-current-state-snapshot.

Source Context

Product direction comes from the Notion project hub Live Character Framework. The source pages checked for this slice are 09 - MVP Roadmap & Open Questions, 02 - Runtime Architecture, 03 - Role Model Loop & Decision Contract, 05 - Living State & Scheduled Life, 06 - Character State Engine & Retrieval Management, and 08 - Runtime Logging & Trace.

Phase 2 starts CharacterRuntimeState by adding current state, a state store, and a state snapshot in DecisionContext. MVP-008 takes only the read-side foothold: a current living-state snapshot can be included in the model input, but no state mutation is accepted or committed yet.

Local implementation truth comes from MVP-001, MVP-002, MVP-003, MVP-004, MVP-005, MVP-006, and MVP-007. The current runtime can complete one USER_MESSAGE turn with visible history and a fake model; the narrow next step is to give that model call a small read-only character-state view.

Goal

Add the smallest Character State Engine read boundary needed for Phase 2: an injected current-state source can provide a validated living-state snapshot to DecisionContext.character_snapshot for a USER_MESSAGE turn. The slice must preserve the MVP-007 user turn flow, keep visible_reply as the only allowed model action, and avoid state commits, state patches, virtual body, incidents, scheduled directives, retrieval, tools, Live2D, concrete storage, and live model providers.

Current Scope

  • One supported event type remains USER_MESSAGE.
  • One optional injected read-only current-state source for tests and callers that have state available.
  • One current-state request built from the normalized runtime event: schema version, trace ID, event ID, event type, optional user ID, and optional conversation ID.
  • One minimal living-state snapshot shape with character_id, current_activity, mood, toward_user, updated_at, and source_event_ids.
  • One optional living_state_brief field inside DecisionContext.character_snapshot when a source returns a snapshot.
  • Existing recent_visible_messages behavior, ordering, budgeting, and current-message exclusion remain authoritative.
  • Existing callers that do not provide a current-state source continue to produce the MVP-007 context shape with only recent_visible_messages.
  • run_user_message_turn() passes the optional state source through to run_role_model_turn(); orchestration order otherwise stays unchanged.
  • Tests use fakes only; no database, file, network, clock, or model provider is introduced.
  • Returned context and result snapshots must preserve copy isolation from source and caller mutation.

Explicit Non-Goals

  • No state mutation, state patch parsing, state commit, state rejection log, state migration, or persistence adapter.
  • No new CharacterDecision action and no change to allowed_actions; it remains ["visible_reply"].
  • No virtual body fields, body drift, need threshold event, active incident, incident queue, scheduled directive, active thread, retrieval index, summaries, compaction, replay UI, tools, Live2D, or assets.
  • No concrete CharacterRuntimeStateStore, database schema, transaction behavior, idempotency policy, or background worker.
  • No live model provider, provider metadata, streaming, retry, timeout, or prompt expansion beyond including the validated snapshot in the existing rendered input.
  • No dedicated context-build raw log entry. The existing role-model turn logs remain the audit record for the rendered model input in this slice.
  • No broad Character State Engine extraction. MVP-008 may add one tiny non-empty Character State Engine read module only for the current-state source protocol, request builder, response validator, and brief mapper required by active tests.
  • No changes to Runtime Kernel route policy beyond preserving the existing MVP-007 USER_MESSAGE route.

Minimal Schema

These TypeScript-style shapes define the intended behavior contract. MVP-008 should implement the contract in Python 3 and test it with unittest.

CurrentCharacterStateRequest

type CurrentCharacterStateRequest = {
  schema_version: "0.1"
  trace_id: string
  event_id: string
  event_type: "USER_MESSAGE"
  user_id?: string
  conversation_id?: string
}

The request intentionally omits character_id. In MVP-008 the injected current-state source is caller-bound to the active character and returns that character's character_id in the snapshot. The implementation must not perform a hidden global character lookup or hard-code a default character ID.

CharacterRuntimeStateSnapshot

type CharacterRuntimeStateSnapshot = {
  schema_version: "0.1"
  character_id: string
  living_state: {
    current_activity: string
    mood: string
    toward_user: string
  }
  updated_at: string
  source_event_ids: string[]
}

MVP008 DecisionContext Excerpt

type DecisionContext = {
  schema_version: "0.1"
  trace_id: string
  event_id: string
  call_type: "user_message_visible_reply"
  event: UserMessageEventContext
  character_snapshot: {
    recent_visible_messages: RecentVisibleMessage[]
    living_state_brief?: {
      character_id: string
      current_activity: string
      mood: string
      toward_user: string
      updated_at: string
      source_event_ids: string[]
    }
  }
  allowed_actions: ["visible_reply"]
}

Functional Requirements

ID Requirement
FR-1 build_decision_context() accepts an optional current-state source in addition to the existing recent visible message source.
FR-2 If no current-state source is provided, build_decision_context(), render_role_model_input(), run_role_model_turn(), and run_user_message_turn() preserve the MVP-007 behavior and context shape.
FR-3 If a source is provided, the Role Model Loop passes the already normalized USER_MESSAGE event into the Character State Engine read contract after validate_normalized_user_message_event() succeeds, and the CSE-owned request builder creates one CurrentCharacterStateRequest.
FR-4 The source is called at most once per role-model turn and before the model adapter receives input.
FR-5 The source response is validated by the tiny Character State Engine read module into the minimal CharacterRuntimeStateSnapshot shape and mapped to DecisionContext.character_snapshot.living_state_brief.
FR-6 The living-state brief preserves trace_id and event_id only through the surrounding DecisionContext; the state snapshot itself must not claim to be the current event.
FR-6a The current-state source is bound by the caller to the active character. The Role Model Loop and user-turn orchestrator must not infer, hard-code, or globally look up character_id.
FR-7 render_role_model_input() validates and preserves living_state_brief when present, and still rejects unknown fields in DecisionContext and character_snapshot.
FR-8 run_role_model_turn() passes the optional current-state source into context building without changing model adapter semantics, failure logging, or parsed decision behavior.
FR-9 run_user_message_turn() accepts the optional current-state source and passes it through to the Role Model Loop without changing Runtime Kernel intake, user visible projection, recent visible source construction, or visible reply commit ordering.
FR-10 Malformed source requests, malformed source responses, unsupported extra fields, empty strings where required, invalid timestamps, or invalid source_event_ids fail before the adapter is called.
FR-11 A state-source validation failure does not append a dedicated raw log entry in this slice and does not append an assistant visible reply.
FR-12 Successful user turns with a state source keep the MVP-007 raw log order: runtime_event_received, user_visible_message_committed, role_model_turn_completed, visible_reply_committed.
FR-13 The final UserMessageTurnResult envelope remains unchanged except that nested role-model input snapshots in raw logs and adapter calls include the living-state brief.

Non-Functional Requirements

  • Use only Python standard library behavior; do not add dependencies.
  • Keep all tests deterministic under injected fake source, fake model adapter, fake raw log, fake visible conversation, fake clock, and fake ID generator.
  • Reuse existing validation helpers from runtime.contracts: reject_extra_keys, require_equal, require_string, require_optional_string, and validate_iso8601_timestamp.
  • Reuse existing constants and behavior from role_model.loop, including USER_MESSAGE_VISIBLE_REPLY_CALL, ROLE_MODEL_INSTRUCTIONS, RECENT_VISIBLE_MESSAGES_MAX_CANDIDATES, RECENT_VISIBLE_MESSAGES_MAX_MESSAGES, and RECENT_VISIBLE_MESSAGES_MAX_TEXT_TOKENS.
  • Do not duplicate Runtime Kernel normalization, route, or raw-log append logic.
  • Keep implementation small and local; add only the Character State Engine read contract plus the optional Role Model Loop and user-turn plumbing required by tests.
  • Copy source-provided snapshots before storing them in context and copy rendered model input before handing it to the adapter, preserving existing mutation isolation expectations.
  • Keep error behavior explicit and testable; do not hide validation failures behind character language.

Test Plan

Unit Tests

  • build_decision_context() without a current-state source preserves the exact MVP-007 minimal context.
  • build_decision_context() with a fake source sends the expected CurrentCharacterStateRequest.
  • build_decision_context() includes a normalized living_state_brief when the fake source returns a valid snapshot.
  • render_role_model_input() accepts the valid living-state brief and rejects extra or malformed fields.
  • Malformed snapshot cases cover missing required fields, empty strings, invalid updated_at, non-list source_event_ids, and non-string source event IDs.
  • Copy isolation: mutating the source response or rendered result after context construction cannot change stored context snapshots.

Integration Tests

  • Run one full user turn with fake current-state source, fake recent visible conversation, fake adapter, fake raw log, deterministic IDs, and deterministic clock.
  • Assert the adapter receives living_state_brief and recent_visible_messages in the same character_snapshot.
  • Assert raw log order remains the MVP-007 order and includes the rendered model input snapshot with the living-state brief.
  • Assert malformed state-source output stops before adapter call and assistant visible reply append.
  • Run full unittest discovery for existing unit and integration tests.

Implementation Boundaries

  • Runtime Kernel remains unchanged except for existing event intake behavior used by MVP-007.
  • Character State Engine ownership is represented by one tiny read module for the current-state source contract; expected path is src/character/state/current.py when production code is added. No durable state store is implemented in this slice.
  • The Role Model Loop may call the Character State Engine read contract while it still assembles the final DecisionContext, but it must not own or duplicate current-state request/response validation.
  • Commit and Effects Engine remains unchanged and continues to accept only the existing visible_reply decision path.
  • The user-turn orchestrator owns only optional dependency plumbing and must not inspect or mutate the state snapshot.
  • Raw Event Log behavior remains unchanged; rendered model input in role_model_turn_completed is enough audit evidence for this slice. Dedicated context-build logging is deferred until a debug/replay or formal context-builder slice.

Error And Fallback Behavior

  • Missing current-state source is not an error; MVP-007 behavior remains valid for callers that do not have state yet.
  • Malformed current-state source output raises the existing role-model validation error type before adapter call.
  • Current-state source exceptions propagate and do not emit fallback character language.
  • Validation failures do not append assistant visible replies, state commits, or repair records.
  • No rollback, retry, reconciliation, or user-visible fallback is added.

Review Notes

  • MVP-008 is a read-only context slice, not a state mutation slice.
  • The slice intentionally chooses living_state_brief instead of a full CharacterRuntimeState object because the model needs compact current reality, not the source-of-truth record.
  • The only reason to touch run_user_message_turn() is optional dependency plumbing; orchestration order and result shape should stay stable.
  • The implementation should choose one tiny non-empty Character State Engine read module for state-source request/response validation and avoid creating empty future folders.
  • Do not broaden this into state patches, body drift, incident interruption, scheduled directives, retrieval, or debug/replay logging.

Open Questions

  • Should absent state eventually produce an explicit default state snapshot? Not in MVP-008; no source keeps the current context shape unchanged.
  • Should the tiny read module later grow into a full context builder? Not in MVP-008; promote that only when a formal context-builder slice owns source orchestration and context-build logging.
  • Should future state snapshots include a state_version separate from schema_version? Park until durable state storage exists.

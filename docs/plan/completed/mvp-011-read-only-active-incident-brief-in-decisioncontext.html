MVP-011 - Read-Only Active Incident Brief in DecisionContext

Source Context

Product direction comes from the Notion project hub Live Character Framework. The source pages checked for this slice are 09 - MVP Roadmap & Open Questions, 02 - Runtime Architecture, 03 - Role Model Loop & Decision Contract, 05 - Living State & Scheduled Life, 06 - Character State Engine & Retrieval Management, and 08 - Runtime Logging & Trace.

Phase 3 starts the Basic Incident System, but the first useful slice should not create or mutate incidents. MVP-011 only lets the existing USER_MESSAGE model call see one compact read-only active incident brief when an injected Character State Engine source provides it.

Local implementation truth comes from completed MVP-001, MVP-002, MVP-003, MVP-004, MVP-005, MVP-006, MVP-007, MVP-008, MVP-009, and MVP-010.

Goal

Add the smallest read-side incident context needed for Phase 3: an optional injected active-incident source that maps one active incident into DecisionContext.character_snapshot.active_incident for the existing USER_MESSAGE role-model call. The slice must preserve current visible-reply and living-state patch behavior.

Current Scope

  • One event type remains in scope: USER_MESSAGE.
  • One new read-side source is in scope: ActiveIncidentSource, injected by the caller.
  • One compact model-facing view is in scope: character_snapshot.active_incident.
  • The source may report no active incident; in that case the current DecisionContext shape is unchanged except for validation support.
  • The active incident view is read-only. It is not committed, resumed, cancelled, completed, queued, interrupted, scheduled, or persisted by this slice.
  • The existing recent-visible-message and living-state brief sources continue to compose into the same character_snapshot.
  • The existing allowed actions remain visible_reply or visible_reply plus state_patch when the living-state write boundaries are fully opted in. MVP-011 does not expose life_action.

Explicit Non-Goals

  • No concrete LifeIncidentStore, database, migration, filesystem store, queue, background worker, scheduler, replay worker, or production persistence adapter.
  • No incident creation, start, complete, cancel, resume, interruption, backgrounding, replacement, deduplication, or reconciliation behavior.
  • No INCIDENT_COMPLETION, TIMER, NEED_THRESHOLD, scheduled directive, tool result, asset result, or maintenance event type.
  • No interrupted_incident, completed incident brief, incident queue, active thread, retrieval result, body state, body drift, Live2D status, proactive message, scheduled directive action, tool request, continuity write, or asset behavior.
  • No new model output action. The model still returns required action = "visible_reply" and may include only the existing optional living-state patch when state patching is allowed.
  • No Runtime Kernel priority or interruption policy changes.
  • No new raw log kind for context building. The existing role_model_turn_failed kind records context-build validation failures; dedicated context-build log kinds stay parked for a later debug/replay slice.

Minimal Schema

ActiveIncidentRequest

type ActiveIncidentRequest = {
  schema_version: "0.1"
  trace_id: string
  event_id: string
  event_type: "USER_MESSAGE"
  user_id?: string
  conversation_id?: string
}

ActiveIncidentSnapshot

type ActiveIncidentSnapshot = {
  schema_version: "0.1"
  incident_id: string
  type: "idle" | "eat" | "drink" | "sleep" | "rest" | "work" | "think" | "wait" | "custom"
  status: "active"
  title: string
  started_at?: string
  expected_end_at?: string
  remaining_seconds?: number
  interrupt_policy: "interruptible" | "background" | "protected"
  resume_policy: "resume" | "ask_model" | "cancel"
  source_event_ids: string[]
}

ActiveIncidentBrief

type ActiveIncidentBrief = {
  incident_id: string
  type: "idle" | "eat" | "drink" | "sleep" | "rest" | "work" | "think" | "wait" | "custom"
  title: string
  started_at?: string
  expected_end_at?: string
  remaining_seconds?: number
  interrupt_policy: "interruptible" | "background" | "protected"
  resume_policy: "resume" | "ask_model" | "cancel"
  source_event_ids: string[]
}

The model-facing brief intentionally omits status because the field name active_incident already carries that meaning. The source snapshot still requires status = "active" so future completed, interrupted, or queued records cannot silently enter this view.

DecisionContext Addition

type DecisionContext.character_snapshot = {
  recent_visible_messages: RecentVisibleMessage[]
  living_state_brief?: LivingStateBrief
  active_incident?: ActiveIncidentBrief
}

Functional Requirements

ID Requirement
FR-1 Without an active_incident_source, existing MVP-010 behavior and tests remain unchanged.
FR-2 When an active_incident_source is provided, Role Model Loop builds an ActiveIncidentRequest from the normalized USER_MESSAGE event, including optional user_id and conversation_id.
FR-3 If the source returns None, the decision context omits character_snapshot.active_incident and continues the normal visible-reply flow.
FR-4 If the source returns one valid active incident snapshot, Role Model Loop maps it to ActiveIncidentBrief, deep-copies it, and places it under character_snapshot.active_incident.
FR-5 Incident validation rejects extra fields, unsupported incident types, non-active status, invalid timestamps, negative remaining_seconds, unsupported policies, missing source IDs, and any source_event_ids containing the current event ID.
FR-6 render_role_model_input() validates active_incident in the same pass as existing recent_visible_messages and living_state_brief.
FR-7 The existing role_model_turn_completed raw log includes the rendered model input with the active incident brief when present. If context build or render validation fails before a model input exists, the existing role_model_turn_failed kind records stage = "context_build" and code = "malformed_context".
FR-8 User-turn orchestration may pass the optional active-incident source through to Role Model Loop, but it must not change state-patch opt-in rules or visible reply commit ordering.
FR-9 Malformed active-incident source output fails before the adapter is called and before downstream living-state patch commit, incident lifecycle commit, and assistant visible-reply commit. The already-committed user visible message projection remains unchanged. The failure appends a role_model_turn_failed raw log with stage = "context_build", but must not append any incident commit, rejection, or lifecycle log because no incident mutation is attempted.

Non-Functional Requirements

  • Use only Python standard library behavior; do not add dependencies.
  • Use fakes for the active-incident source, raw log, visible conversation, current-state source, role-model adapter, clock, and IDs.
  • Follow the existing character.state.current request/build/validate pattern for the new active-incident read helper.
  • Keep incident validation explicit and local to the Character State Engine read-side helper. Do not hide it in prompt text.
  • Do not add a new shared contract module unless implementation shows two real production consumers in this slice.
  • Deep-copy source output, context entries, rendered model input, and raw-log model-input snapshots so caller mutation cannot alter audit data.
  • Keep Runtime Kernel and Commit and Effects behavior unchanged.
  • Keep Role Model Loop output parsing unchanged: active-incident context may inform the fake adapter, but it does not authorize life_action.

Acceptance Criteria

  • Existing MVP-001 through MVP-010 tests continue to pass.
  • A user turn with a valid active-incident source renders character_snapshot.active_incident to the adapter and records it in the existing role-model turn log.
  • A user turn with no active incident preserves current behavior and omits the field.
  • Malformed incident source output fails before model adapter invocation and appends a role_model_turn_failed raw log with stage = "context_build".
  • State-patch-enabled turns still require the current-state source, prepare store, and atomic finalizer; adding an incident source alone does not opt into state writes.
  • No concrete incident store, incident lifecycle transition, interruption policy, new event type, body state, retrieval, tool, Live2D, scheduler, provider call, or new model action is added.
  • The development journal records source context, files touched, checks run, review notes, and next action.
  • Future ideas discovered during planning are recorded in future-slices.html.

Test Plan

Unit Tests

  • Build and validate ActiveIncidentRequest from a normalized USER_MESSAGE, including optional user and conversation IDs.
  • Map a valid ActiveIncidentSnapshot to ActiveIncidentBrief and verify deep-copy behavior.
  • Reject malformed snapshots for extra fields, unsupported types, non-active status, bad timestamps, bad policies, negative remaining seconds, missing source IDs, and current-event source IDs.
  • Build DecisionContext with no source, source returning None, source returning a valid active incident, and source returning malformed output.
  • Render role-model input with active_incident and reject manually mutated future fields under character_snapshot.active_incident.
  • Build a context-failure raw log entry that records the normalized event and failure details without claiming a model input exists.
  • Assert allowed actions are unchanged by active-incident context.

Integration Tests

  • Run one user turn with a fake active-incident source and assert the adapter sees the brief under character_snapshot.active_incident.
  • Assert the role_model_turn_completed raw log stores the same active incident brief in the rendered model input.
  • Assert malformed current-state and active-incident context failures append role_model_turn_failed with stage = "context_build" while preserving the already committed user visible message and skipping the adapter and assistant reply.
  • Run one user turn with the source returning None and assert current visible reply behavior is preserved.
  • Run one state-patch-enabled user turn with both current state and active incident sources to prove the two read-side context entries compose without changing commit order.
  • Run full unittest discovery.

Implementation Boundaries

  • Runtime Kernel remains unchanged.
  • Character State Engine owns the new active-incident request, snapshot validation, and brief-building helper.
  • Role Model Loop owns placing the validated brief into DecisionContext, rendering it, and logging success or validation failure through existing role-model turn log kinds.
  • User-turn orchestration may pass the optional active-incident source through to Role Model Loop.
  • Commit and Effects remains unchanged because no incident decision is accepted or committed.
  • Raw Event Log behavior changes only insofar as existing role-model turn logs may contain the new context field or a context_build failure for malformed context inputs.

Implementation Results

  • Added ActiveIncidentRequest, ActiveIncidentSnapshot, ActiveIncidentBrief, and ActiveIncidentSource to the Character State Engine read contracts in src/character/state/current.py.
  • Reused one private USER_MESSAGE read-request envelope helper for both current-state and active-incident sources, so optional user_id and conversation_id are derived consistently from the normalized event.
  • Mapped valid active incident snapshots into model-facing briefs and rejected extra fields, unsupported types, non-active status, invalid timestamps, negative or boolean remaining_seconds, unsupported policies, missing source IDs, and current-event source IDs.
  • Threaded the optional active-incident source through build_decision_context(), run_role_model_turn(), and run_user_message_turn() without changing Runtime Kernel, Commit and Effects, allowed actions, state-patch opt-in, visible reply commit ordering, or model output parsing.
  • Kept success logging on the existing role_model_turn_completed raw log by validating and rendering character_snapshot.active_incident inside the role-model input snapshot.
  • Added role_model_turn_failed logging for malformed context-build/render failures before adapter invocation, using stage = "context_build" and code = "malformed_context".
  • Added unit and integration coverage for valid active incident context, absent active incidents, malformed source output before adapter invocation, context-build failure logging, render-time validation, deep-copy behavior, pass-through from user-turn orchestration, and composition with living-state patch commits.

Review Notes

  • MVP-011 is the read-side incident equivalent of MVP-008, not the incident lifecycle implementation.
  • The field name should stay aligned with Notion's compact context shape: character_snapshot.active_incident.
  • If implementation pressure suggests interrupted_incident, life_action, event priority, or lifecycle commits, park those as future slices.
  • The source snapshot's status = "active" guard is the compatibility boundary that prevents queued, interrupted, completed, or cancelled records from leaking into this MVP's model-facing view.

Open Questions

  • Should the eventual concrete incident store use append-only lifecycle records or mutable current rows? Not in MVP-011.
  • Should user messages convert active_incident into interrupted_incident before the model call? Not in MVP-011.
  • Should active incidents affect allowed actions by exposing life_action? Not in MVP-011.

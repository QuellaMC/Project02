MVP-001 - Basic Relay CLI

Status: completed

Created: 2026-06-03. Completed: 2026-06-03. Archived spec: docs/plan/completed/mvp-001-basic-relay-cli.html. Runtime language: TypeScript. Test runner: Vitest.

Source Context

Product direction comes from the Notion project hub Live Character Framework. Relevant source pages are 01 - Framework Overview, 02 - Runtime Architecture, 04 - Event Triggers & Runtime Hooks, and 08 - Runtime Logging & Trace.

Notion direction: build toward a Live Character Framework where triggers eventually become runtime events, model output proposes actions, and runtime policy commits accepted behavior.

Local rebuild direction comes from AGENTS.md and AGENTS.repo.md. The reset main line is intentionally small. The old TypeScript implementation on legacy/typescript is reference material only. The first new product slice should be a small OpenClaw-style relay path: one input, a minimal agent seam, and one output.

Goal

Implement the smallest runnable message relay: a user provides one message through a CLI command, the command passes that message through a minimal local agent seam, and the CLI prints exactly one reply to standard output.

Current Scope

  • One CLI entry point at src/relay-cli.ts, with a package-script wrapper for manual runs.
  • One input path: exactly one non-empty single-line command-line message.
  • One output path: the CLI itself prints exactly one reply line to stdout.
  • A small pure relay function that accepts message text and an injected agent seam.
  • A deterministic local agent implementation for this slice.
  • Input trimming and validation for missing, empty, whitespace-only, or multi-line messages.
  • Non-zero process exit and a clear stderr message when CLI input is invalid.
  • Focused tests for the pure relay behavior and CLI boundary behavior.

Explicit Non-Goals

  • No live model provider call.
  • No API key, provider config, prompt template, or model selection.
  • No Twilio, WhatsApp, webhook, HTTP server, browser UI, or provider edge.
  • No RuntimeEvent implementation.
  • No RawEventLog, trace store, durable persistence, or replay surface.
  • No Character State Engine, Role Model Loop, Commit and Effects Engine, or Runtime Kernel module.
  • No memory, retrieval, tools, scheduler, Live2D, assets, plugin system, or background worker.
  • No multi-turn conversation state or transcript storage.
  • No compatibility migration from the old legacy/typescript branch.

Minimal Contract

RelayAgent

type RelayAgent = {
  reply(input: { message: string }): Promise<{ text: string }> | { text: string }
}

RelayResult

type RelayResult = {
  input: {
    message: string
  }
  reply: {
    text: string
  }
}

CLI Contract

node src/relay-cli.ts -- "are you there?"

# stdout
relay: are you there?

# package-script smoke example
pnpm --silent relay -- "are you there?"

The relay agent seam is intentionally smaller than the future role-model boundary. It is the first executable pressure point for the message path. Future slices may replace or wrap it with runtime events, model calls, logging, and commit/effect boundaries after this command works.

Functional Requirements

ID Requirement
FR-1 The repo exposes a CLI command named relay through pnpm relay.
FR-2 The CLI accepts exactly one non-empty single-line message from command-line arguments.
FR-3 The CLI rejects missing, empty, whitespace-only, or multi-line input before calling the agent seam.
FR-4 The pure relay function passes the normalized message to the injected agent seam.
FR-5 The relay function returns the agent reply text without adding durable state or side effects.
FR-6 The CLI prints exactly one successful reply to stdout and does not print success output to stderr.
FR-7 Invalid CLI input exits non-zero and prints a clear error to stderr.
FR-8 The deterministic local agent returns a stable reply suitable for tests and manual smoke runs.

Non-Functional Requirements

ID Requirement
NFR-1 No network call or external service is used.
NFR-2 No live model provider is called.
NFR-3 Runtime behavior is deterministic for the same CLI input.
NFR-4 The implementation remains small and runnable on the current TypeScript baseline.
NFR-5 The slice introduces no empty folders or placeholder modules for future architecture.
NFR-6 Tests do not depend on Notion, GitHub, local machine state, or provider credentials.

Acceptance Criteria

ID Criterion
AC-1 node src/relay-cli.ts -- "hello" prints exactly relay: hello plus a trailing newline to stdout.
AC-2 Blank or multi-line input is rejected with a non-zero exit code and a stderr error.
AC-3 A unit test proves the relay function calls the injected agent seam with the normalized message.
AC-4 A unit test proves invalid input does not call the agent seam.
AC-5 A CLI boundary test proves stdout/stderr behavior for success and invalid input.
AC-6 pnpm lint, pnpm typecheck, and pnpm test pass.
AC-7 No old runtime modules are restored from legacy/typescript.

Test Plan

Unit Tests

  • Relays a valid message to an injected fake agent.
  • Trims input before passing it to the agent.
  • Returns the fake agent reply text.
  • Rejects missing, empty, whitespace-only, and multi-line input.
  • Proves rejected input does not call the agent.

CLI Boundary Tests

  • Successful direct Node command prints exactly one CLI-owned reply line to stdout.
  • Successful command leaves stderr empty.
  • Invalid command exits non-zero.
  • Invalid or multi-line command input prints a clear stderr error and no stdout reply.

Implementation Boundaries

  • The CLI boundary owns argument parsing, stdout, stderr, and process exit code mapping.
  • The pure relay function owns message normalization, validation, agent invocation, and reply validation.
  • The local agent owns only a deterministic reply for this first runnable path.
  • The implementation may add a small CLI file and a small relay module, but should not create the future runtime directory structure.
  • Tests should execute the TypeScript CLI directly with node src/relay-cli.ts so package-manager output cannot affect the stdout contract.

Failure Behavior

  • Invalid user input, including embedded line breaks, returns a validation error before the agent seam is called.
  • An empty, whitespace-only, or multi-line agent reply is treated as an implementation error and should fail the relay call.
  • The CLI maps validation failures to a clear stderr message and a non-zero process exit.
  • The CLI maps unexpected agent failures to a clear stderr message and a non-zero process exit without pretending the character answered.

Pre-Code Review Notes

  • The reset branch currently contains only a callable TypeScript health baseline and one test.
  • This slice intentionally chooses the OpenClaw-style product path over replaying the old MVP-001 runtime-event/logging implementation.
  • The old legacy/typescript branch may be checked for naming or failure-case inspiration, but it must not be copied wholesale.
  • The relay agent seam is the only abstraction justified by this slice because it gives future model/provider work a small replacement point.
  • Runtime events and raw logs remain long-term architecture goals from Notion, but they should be introduced only when the working relay path creates real pressure for them.

Open Questions

  • No product decision is currently blocked. The implementation should proceed with an argv-based CLI unless the user chooses a different first input path.

Future Ideas Parking Lot

  • Add verbose structured logs after the CLI has enough operational pressure.
  • Add a live model adapter after the local relay seam is proven.
  • Add one provider edge, such as Twilio, after the CLI relay works.
  • Introduce RuntimeEvent and raw trace logging once the message path has a concrete event boundary to preserve.

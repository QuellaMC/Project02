Functional Spec: Project Initialization

Status: implemented

Source Context

This spec is derived from the Notion database Live Character Framework, especially the framework overview, runtime architecture, role model loop, and MVP roadmap pages.

"Build the runtime first using the four-module architecture."

Goal

Initialize the repository so future work can proceed in small, reviewed, TDD-driven slices without adding premature runtime code or empty module folders.

Functional Requirements

  • Create local documentation roots: docs/wiki, docs/plan, and docs/develop-journal.
  • Create a date-scoped journal folder for 2026-05-14.
  • Create top-level src as the future source root, without domain module folders.
  • Create tests/unit and tests/integration roots for TDD work.
  • Write HTML documentation that links Notion sources, local docs, source policy, and test policy.
  • Record a development workflow that requires spec review before code and code review after code.
  • Identify the next small candidate implementation slice without implementing it.

Non-Functional Requirements

  • Modularity: no module-specific source directories until a TDD slice needs them.
  • Security: ignore local secrets such as .env files by default.
  • Efficiency: keep docs concise and link to source pages instead of duplicating the whole Notion spec.
  • Maintainability: local docs must be browsable as static HTML files.

Acceptance Criteria

Criterion Result
Repository has wiki, plan, and develop-journal documentation roots. Met
Repository has source and test roots, with unit and integration test areas. Met
No runtime implementation module is added during initialization. Met
Docs link to Notion source pages and local related files. Met
Workflow documents TDD, pre-code review, and post-code review expectations. Met

Implementation Notes

This slice intentionally does not choose a language, runtime package manager, database, model provider, or test runner. Those choices belong to the first runtime slice functional spec, where they can be reviewed against the actual behavior being implemented.

Review Notes

  • No existing source logic was present in the repository, so no code reuse was possible.
  • Only root-level source and test folders were created; runtime module boundaries remain uncommitted.
  • The next runtime slice should avoid model calls and persistence details beyond an interface until the contract is tested.

Source Layout Full Reset - Plugin-Named

Status: active implementation

Created: 2026-06-15. Active spec: docs/plan/active-slice.html. Implementation branch: feature/mvp-007-agent-capabilities.

Goal

Reset the pre-release source layout and public surface so the repository is organized around current product boundaries instead of old MVP compatibility paths. The reset keeps plugin terminology and keeps the MVP-007 plugin host direction.

Before and After

Before After
Most production files lived directly under src/, and many tests imported through a broad src/index.ts barrel. Source code is grouped under cli/, core/, runtime/, runtime/storage/, role-model/, and plugins/. Tests import concrete modules.
The old relay command and relay tests stayed as compatibility scaffolding. pnpm chat and pnpm inspect are canonical. Relay code and script entries are removed.
character_state.patch was defined both as a built-in model tool and as built-in plugin behavior. visible_reply is the only built-in visible output tool. character_state.patch is owned by the Character State plugin.
Top-level role-model text could look like a visible output path. Top-level text is folded model text: hidden by default, optionally shown by CLI toggle, and never committed as visible conversation.
Adapter fixture mappers were exported beside production plugin APIs. Adapter proof mappers live under src/plugins/adapter-proofs/ and are not part of the production plugin index.

Scope

  • Break old import paths, old CLI scripts, and compatibility-only tests because there is no official release.
  • Keep plugin names and RuntimePlugin* types.
  • Keep canonical chat, inspect, local runtime storage, role-model toolCalls, folded top-level text, and plugin evidence behavior.
  • Keep role-model decision versions internal: providers return toolCalls and optional folded text, while the runtime stamps durable decision versions.
  • Keep OpenClaw, Hermes, TencentDB, and MCP real-shape adapter proofs as fixture proof code.

Implementation Boundaries

  • src/index.ts remains a tiny package health entrypoint, not an internal dependency barrel.
  • Runtime code imports concrete modules directly.
  • Plugin-host validation decides which executable tools are model-facing for a turn.
  • No storage or CLI migration layer is added.

Acceptance Criteria

  • No production or test imports reference old top-level source files removed by the reset.
  • No relay command, relay module, or relay tests remain.
  • character_state.patch appears in role-model decisions only through plugin-provided tool definitions.
  • Provider prompts do not ask the model to emit a top-level version; parsed decisions still carry the internal role-model contract version.
  • Folded top-level text tests prove it is hidden by default and not committed as visible conversation.
  • pnpm check, strict unused-symbol TypeScript, git diff --check, and chat plus inspect smoke pass.

MVP-005 - Structured Role-Model User Turn Foundation

Status: implemented locally, final integration review in progress

Created: 2026-06-09. Updated: 2026-06-09. Active spec: docs/plan/active-slice.html. Previous slice archived at docs/plan/completed/mvp-004-durable-local-runtime-continuity.html. Suggested implementation branch: feature/mvp-005-structured-role-model-user-turn.

Implementation Status

CT-01 through CT-04 are integrated in the local working tree, and CT-05 now exposes the stored evidence through inspect. The implementation is still deliberately local/fake-adapter only and accepts only visible_reply decisions. It does not include a live provider, retrieval, scheduler, tools, Live2D, replay mutation, or full runtime-kernel restoration.

Durable role-model evidence is attached to existing terminal raw event records as optional roleModelIOSnapshot, parsedRoleModelDecisionSnapshot, and commitValidation snapshots. Inspect renders that decoded raw-event evidence as a read-only roleModelEvidence object containing the input envelope summary, raw adapter output text, parsed decision status, and commit validation status.

Source Context

Product direction comes from the Notion project hub Live Character Framework, especially 01 - Framework Overview, 02 - Runtime Architecture, 03 - Role Model Loop & Decision Contract, 06 - Character State Engine & Retrieval Management, 08 - Runtime Logging & Trace, and 09 - MVP Roadmap & Open Questions.

Long-term direction: the role model should receive a compact DecisionContext, return one structured CharacterDecision, and let the runtime validate, commit, log, and emit effects.

Local rebuild direction comes from AGENTS.md and AGENTS.repo.md. This slice must grow from the current working durable local chat path. It should introduce the first role-model-shaped user turn without adding retrieval, scheduling, tools, provider calls, Live2D, or a full Runtime Kernel.

Current Product Before This Slice

MVP-004 gives the repo a durable local chat path. A user can run chat, talk to Mira, exit, resume a stored session, and inspect per-session runtime trace, raw event, and visible conversation evidence after the process exits. 

terminal input
  -> create USER_MESSAGE RuntimeEvent
  -> local runtime adapter handles the event
  -> deterministic character agent writes visible reply
  -> append durable trace, raw event, and conversation records
  -> chat CLI prints Mira's reply

The limitation is that the "character mind" is still a small local reply function. There is no role-model input envelope, no explicit DecisionContext, no structured CharacterDecision, no parsed model output, no model I/O snapshot, and no commit/effects validation boundary that can later host a real model safely.

Product After This Slice

Local chat should become the first structured role-model user turn. The visible chat may look the same at first, but every non-exit user message now flows through a model-shaped boundary: compact context is built, a local role-model adapter proposes a structured decision, runtime validation accepts or rejects that decision, and durable logs explain what happened. 

terminal input
  -> create USER_MESSAGE RuntimeEvent
  -> build compact DecisionContext from the durable local session
  -> render RoleModelInputEnvelope
  -> local role-model adapter returns a raw decision payload
  -> parse CharacterDecision
  -> validate supported effects for this slice
  -> commit accepted visible reply or durable rejection evidence
  -> chat CLI prints Mira's reply when accepted

This is not smarter memory yet. Mira does not retrieve old facts, call a live model, execute tools, schedule future work, or change Live2D state in this slice. MVP-005 only creates the first real "model proposes, runtime commits" user-turn foundation so later slices can add those capabilities without duplicating the chat, storage, or validation paths.

Goal

Replace the direct deterministic reply call inside the local user-message path with a structured role-model loop foundation. The slice should define shared decision contracts, build a minimal DecisionContext, route user turns through a local/fake role-model adapter, parse and validate CharacterDecision output, persist model/decision/commit evidence, and keep existing durable chat behavior compatible.

Current Scope

  • One local role-model loop for the existing USER_MESSAGE chat path only.
  • Shared TypeScript contracts for DecisionContext, RoleModelInputEnvelope, CharacterDecision, allowed actions, model I/O snapshots, and decision rejection reasons.
  • A minimal user-turn context builder that includes the current event, local character profile, selected recent visible messages, session identity, and runtime notes.
  • A local/fake role-model adapter that can preserve current deterministic reply behavior while returning structured decision-shaped output.
  • Parsing and validation for the MVP-005-supported visible_reply decision shape.
  • A commit/effects boundary that accepts valid visible replies, rejects malformed or unsupported decisions, and prevents rejected decisions from fabricating visible conversation messages.
  • Durable model/decision/commit evidence stored as MVP-005 trace/raw-event evidence in the existing per-session files, without creating a parallel storage root, model I/O store, or log system.
  • Chat CLI routing through the new user-turn path while preserving the MVP-004 default chat, session resume, trace mode, and relay compatibility.
  • Inspect CLI output that can show the new role-model evidence for a stored turn without mutating runtime state.

Explicit Non-Goals

  • No live OpenAI, Anthropic, local LLM, or other real model provider call.
  • No API key handling, provider config, model selection, streaming, retries, or cost tracking.
  • No semantic memory, retrieval index, embeddings, summaries, exact source expansion, relationship memory, or compaction.
  • No scheduler, ScheduledDirective store, timers, reminders, due events, background worker, or proactive delivery.
  • No tools, external side effects, documents, calendars, accounts, permissions matrix, authentication, or user-data sync.
  • No Twilio, WhatsApp, webhook, HTTP server, browser UI, mobile app, or external provider edge.
  • No living state, virtual body, incident lifecycle, Live2D semantic status, asset registry, or visual rendering layer.
  • No full Runtime Kernel, Character State Engine, Role Model Loop, or Commit and Effects Engine restoration from legacy/typescript.
  • No replay UI and no re-execution of model calls from stored logs.
  • No public API break for MVP-001 relay, MVP-002 conversation core, MVP-003 trace mode, or MVP-004 durable local sessions unless this draft is explicitly revised.

Finished Slice

Before MVP-005 After MVP-005
User messages call a deterministic character agent directly. User messages route through a structured role-model loop with a local adapter.
The runtime records what event happened and which visible messages were committed. The runtime also records what context was shown, what decision was proposed, and whether commit validation accepted or rejected it.
There is no stable place for a real model provider to plug in later. The provider seam is explicit, but still backed by a local/fake adapter in this slice.
Invalid reply output is a local agent validation failure. Invalid model-shaped output becomes a durable rejected runtime outcome with no fake visible messages.
Inspect can show sessions, traces, raw events, statuses, and visible messages. Inspect can also show raw-event-attached model input/output snapshots, parsed decision status, commit validation status, accepted visible reply text, and rejection reason for a selected turn.
Future retrieval, memory, tools, scheduling, and real model support would need to invent their own decision path. Future slices can reuse one user-turn decision path and add capabilities behind explicit contracts.

Parallel Child Tasks

This draft is intentionally shaped for five large, independently owned subthreads. CT-01 must freeze the shared decision contracts, exported types, rejection taxonomy, and fixtures first. CT-02 through CT-05 should consume those exports; if they start before CT-01 is merged, they should write contract-facing tests or adapter scaffolding rather than creating alternate production decision shapes.

  • CT-01 - Decision Contracts
  • CT-02 - User-Turn Context Builder
  • CT-03 - Role Model Loop
  • CT-04 - Commit And Effects Validation
  • CT-05 - CLI, Inspect, Integration Review, And Docs

Implementation Boundaries

  • A new shared decision-contract module owns DecisionContext, RoleModelInputEnvelope, CharacterDecision, allowed actions, model/decision snapshot shapes, and rejection reason names.
  • The user-turn context builder owns compact context construction from existing conversation/session/runtime data. It does not retrieve old memory or open arbitrary raw stores.
  • The Role Model Loop owns envelope rendering, local adapter invocation, raw output capture, decision parsing, and malformed-output rejection.
  • The commit/effects boundary owns validation of supported decisions and routes accepted visible replies through existing conversation/runtime log behavior without re-running the role-model adapter.
  • The existing conversation core remains the owner of visible message shape, local character profile, transcript validation, deterministic reply semantics, recent-message selection, and restored transcript rules unless this draft is explicitly revised.
  • If accepted-decision commit needs a narrower conversation seam, extract it from the existing conversation core instead of copying message ID allocation, recent-message selection, reply validation, or transcript mutation logic.
  • The existing local storage, file runtime log store, and session store remain the only durable local storage layout for this slice.
  • src/chat-cli.ts owns terminal UX, session flags, trace output, and clear error messages.
  • src/inspect-cli.ts owns read-only debug output and must not mutate runtime state.
  • The relay command remains the MVP-001 smoke path and should not move into the role-model path in this slice.

Minimal User Experience

  • pnpm chat should still print Mira is ready., prompt for input, and print Mira's accepted visible replies.
  • For accepted turns, visible text can remain identical to MVP-004 while the engine now records role-model evidence.
  • For rejected model decisions, the CLI should report a clear runtime error and must not append fake visible messages.
  • pnpm chat -- --trace should keep JSON Lines trace summaries on stderr and may include role-model/commit decision status when useful.
  • pnpm inspect -- --store <path> --session <session-id> should expose the raw-event-attached roleModelEvidence object for debugging without replaying or mutating a turn.

Test Plan

  • Contract tests for decision shape, allowed actions, model I/O snapshots, rejection reasons, immutability, and unsupported fields.
  • Context-builder tests for recent visible message selection, event placement, session identity, runtime notes, no current-message duplication, and immutable output snapshots.
  • Role-model-loop tests for valid local adapter output, malformed output, unsupported actions, parser failures, and raw-output capture.
  • Commit/effects tests for accepted visible replies, rejected empty/multiline replies, unsupported decision effects, no fake visible commits, and durable rejection evidence.
  • Integration tests that run chat, reopen the store, inspect role-model evidence, resume the session, and preserve MVP-004 deterministic second-turn behavior.
  • CLI boundary tests for default chat, --store, --session, --new-session, trace mode, inspect output, clear errors, and relay compatibility.
  • Docs and HTML sanity checks for active slice, child task packets, and dated journal updates.

Review Decisions Requested

  • Slice status: this draft proposes a structured role-model foundation before retrieval, scheduling, tools, Live2D, or provider support.
  • Provider scope: this draft proposes only a local/fake role-model adapter; a live model provider remains a later explicit slice.
  • Decision scope: this draft proposes accepting only visible_reply decisions, while defining the shared contract narrowly enough to extend later.
  • Storage strategy: this draft proposes reusing the MVP-004 local runtime truth layer by extending existing trace/raw-event records for model/decision/commit evidence rather than creating a separate model log store or new per-session file.
  • Context scope: this draft proposes recent visible messages and runtime notes only; semantic retrieval and exact source expansion remain later slices.
  • Compatibility: this draft proposes stable user-facing chat output unless a concrete implementation conflict requires a reviewed compatibility note.

Future Pressure

Once the local user turn has a real DecisionContext, RoleModelInputEnvelope, CharacterDecision parser, and commit/effects validation path, later slices can add live model providers, semantic retrieval, compact context budgeting, scheduled directives, tool requests, Live2D semantic status, provider webhooks, or richer replay. Those later slices should reuse this role-model user-turn foundation instead of inventing separate decision paths.
